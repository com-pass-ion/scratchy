# Prompt Templates for 32B Models

This file contains optimized prompt templates designed for 32B models, following
the project's cycle rules and commit convention. Templates are atomic, self-contained,
and designed to minimize token usage while maintaining clarity.

## Template Conventions

- **Atomic units**: Each prompt addresses one logical task
- **Commit convention**: `<type>(<scope>): <description> [C<N>] [Xsp] [#item]`
- **English only**: All documentation and prompts in English
- **Minimal context**: Read only necessary files, use targeted grep/search
- **Stop conditions**: Commit and log state when approaching token limits

## Template 1: Backlog Review and Triage

**Purpose**: Review BACKLOG.org, triage items, suggest next cycle selection

```
You are working on an Emacs configuration project called "Scratchy".

## Project Structure
- src/init.el - Main config
- tests/ - Tests (run with ./tests/run_tests.sh)
- docs/ - Documentation (SCRUM.org)
- cycle/ - Cycle process, backlog, cycle tracking

## Current Cycle
Cycle N: [goal/velocity]

## Task
Review the product backlog and suggest items for the next cycle.

## Backlog Categories
:editor:, :devops:, :testing:, :docs:, :lang:, :ai:, :cpp-dev:, :debug:

## Instructions
1. Read cycle/BACKLOG.org
2. Identify DONE vs TODO items
3. Group TODO items by category and estimated effort
4. Recommend 3-5 items for next cycle considering:
   - Total effort ≤ 16 story points (typical capacity)
   - Dependencies between items
   - Risk / unknowns
5. Output in this format:

### Suggested Cycle Items
- [Cycle N] <type>(<scope>): <description> [C<N>] [Xsp] [#item]

### Item Details
- **<item>**: Brief description with acceptance criteria
- **Effort**: Story points (1-5 scale)
- **Risks**: Known blockers or uncertainties

## Quality Checks
- Do not mix unrelated changes in a single prompt
- One logical change per prompt (atomic)
- Follow commit convention: type(scope): description
- Keep prompts simple for 32B models - break complex work into units
- Document context minimization guidelines when relevant
