* Scratchy — Technical Specification

** Overview

- *Project*: Scratchy — minimal, modern, workflow-oriented
- *Author*: Nico Josef Hechler
- *Emacs Version*: 30.1
- *Platform*: Linux (RaspiOS / Ubuntu)
- *Purpose*: multi-purpose, workflow-oriented, classical emacs config
- *Supported Languages*: Python, C/C++, Java, Bash, Elisp

** Design Philosophy

- *Built-in first*: Use Emacs built-ins where possible (eglot, project.el, tempo, flymake, which-key)
- *Minimal packages*: Only add packages that provide clear, measurable value
- *Single-file config*: Everything in =src/init.el=, no modular splitting
- *Testable*: Every feature has an automated test (143 module + 32 integration tests, TAP format)
- *Workflow*: Every workflow has a predefined usage-test automated and user reviewed.
- *Documented*: Documentation lives in ./doc as WORKFLOWS.org & SCRUM.org
- *Session-tracked*: Scrum-style changelog in log/SESSION.org

** Development Workflow

- *Commit after every step*: After completing each task or feature, commit the changes immediately with a descriptive message
- *Test before commit*: Run =./test/run_tests.sh= to verify all tests pass before committing
- *Update log/SESSION.org*: Log completed work in the scrum-style changelog before committing

** Workflow Patterns

*** Quick Edit
1. =C-x C-r= — open recent file
2. Edit with electric-pair + corfu auto-completion
3. =C-c l r= — run (mode-specific)
4. =M-n= / =M-p= — navigate errors

*** Git Workflow
1. Edit code — diff-hl shows changes in fringe
2. =M-x magit-status= — stage, commit, push
3. =C-x v = — review diff inline

*** Multi-Window
1. =C-x 2= — split horizontal
2. =C-c t n= — open terminal in bottom
3. =M-o= — jump between windows (a/s/d/f/g/h/j/k/l)

*** New Project
1. =M-x my/project-new= — scaffold C++ or Python project
2. Auto: git init, .gitignore, boilerplate, venv (Python)

** Language-Specific Workflows

*** Python
- LSP: pyright (auto-starts, basic type checking)
- Run REPL: =C-c C-c= (send buffer)
- Run script: =C-c l r= (compile)
- Snippet: =python-main= + =C-<TAB>=

*** C/C++
- LSP: clangd (C++17 / C11 flags)
- Build: =C-c l b= (CMake)
- Run: =C-c l r= (build + execute)
- Snippet: =c-main= + =C-<TAB>=

*** Bash
- LSP: bash-language-server (auto-starts)
- Run: =C-c l r=
- Snippet: =bash-header= + =C-<TAB>=

*** Java
- LSP: jdtls (auto-detected)
- Run: via eglot

*** Elisp
- Run: =C-c l r= (eval-buffer)
- Eval last sexpr: =C-x C-e=
- Snippet: =elisp-func= + =C-<TAB>=

* Scrum Workflow

** Rules

- *English Only*: All documentation must be written in English for consistency
- *No Features Without Approval*: Only implement features when explicitly approved
- *No New Features Without Approval*: Only add new items to backlog with confirmation
- *Planning Poker*: Estimation before sprint planning for new items
- *Definition of Done*: All code must pass tests, be documented, and follow style guide
- *Sprint Goal*: Each sprint must have a clear, measurable goal
- *Phase Tracking*: Update =current_state.org= on every phase change

** Planning Poker

*** Process
1. Select item from log/BACKLOG.org
2. Each person shows SP simultaneously (● to ●●●●●)
3. Discuss if difference > 2 SP
4. Consensus → update :Effort: in log/BACKLOG.org
5. No consensus → split or break down item
