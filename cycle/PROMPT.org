* Role

You are working on an Emacs configuration project called "Scratchy".

** Overview
- *Project*: Scratchy — minimal, modern, workflow-oriented
- *Emacs Version*: 30.1+
- *Platform*: Linux (RaspiOS / Ubuntu)
- *Purpose*: multi-purpose, workflow-oriented, classical Emacs config
- *Supported Languages*: Python, C/C++, Java, Bash, Elisp

** Design Philosophy
- *Built-in first*: Use Emacs built-ins where possible (eglot, project.el, flymake, which-key)
- *Minimal packages*: Only add packages that provide clear, measurable value
- *Single-file config*: Everything in =src/init.el=, no modular splitting
- *Testable*: Every feature has an automated test (162 module + 33 integration, TAP format)
- *Workflow*: Every workflow has a predefined usage-test, automated and user reviewed.
- *Documented*: Primary specification lives in this file.
- *Commit-driven*: Cycle tracking via conventional commits with =[C<N>]= markers

* Language-Specific Workflows

** Python
- LSP: pyright (auto-starts, basic type checking)
- Run REPL: =C-c C-c= (send buffer)
- Run script: =C-c l r= (compile)
- Snippet: =def= + =M-+=

** C/C++
- LSP: clangd (flags from build/compile_commands.json via project .clangd)
- Build: =C-c l b= (project-compile → make → CMake backbone)
- Debug: =M-x gdb= (stock; layout + tooltips; pretty-printing via default =.gdbinit= in =scaffold/templates/=)
- Run: =C-c l r= / =make run= (built binary)
- Snippet: =if= / =for= + =M-+=

** Bash
- LSP: bash-language-server (auto-starts)
- Run: =C-c l r=
- Snippet: =fun= + =M-+=

** Java
- LSP: jdtls (auto-detected)
- Run: via eglot

** Elisp
- Run: =C-c l r= (eval-buffer)
- Eval last sexpr: =C-x C-e=
- Snippet: =fun= + =M-+=

* Cycle Rules for Agents

** Language
- *English Only*: All documentation must be written in English

** Features
- *No Features Without Approval*: Only implement features when explicitly approved. Only add new items to backlog with confirmation.
- *Backlog Tasks: DONE not Deleted*: Tasks removed from backlog must be marked as DONE, not deleted

** Quality
- *Definition of Done*: All code must pass tests, be documented, and follow style guide. For configuration changes, passing the Absolute-Pass (Source Build + Compile) is required.
- *Test Before Commit*: Run =./test/run_tests.sh= before committing
- *Commit After Every Step*: Commit after completing each task with descriptive message
- *Atomic Commits*: Each commit must be self-contained and reversible. One logical change per commit. Never mix unrelated changes (e.g. a code fix and a docs update) in a single commit.
- *Dependencies Required*: When adding packages with system dependencies, always update the installation script.
- *Dependency Gate*: Verify package availability and system dependencies during planning. Do not commit to a cycle item if its core dependencies are unverified.
- *Test Strategy*: Tests must verify functionality, not just code presence. Use feature tests (=fboundp=), state tests (=bound-and-true-p=), and integration tests (file open). Source-level tests only for critical configs (fonts, keybindings).
- *Research Documents Exempt from Tests*: Documentation-only files in =doc/agent-research/= and similar research directories do not require test coverage. Research is documentation, not code.
- *Blueprint Requirement*: Research tasks must conclude with a "Prototype/Implementation Sketch" section. This transforms abstract findings into a concrete blueprint for future implementation.

** Agent Safety
- *Context Limits*: If session runs out of tokens or context becomes too large, STOP. Do not continue with partial work. Commit what exists, log state, and start fresh in a new session.
- *Session Restart Protocol*: On session restart, read =cycle/BACKLOG.org= first. Do not re-read all project files; read only what the current task needs.
- *Minimal Reads*: Read only: =cycle/BACKLOG.org=, relevant task file, and max 2-3 supporting files. Do not batch-read the entire project.
- *Prompt Complexity*: Keep prompts simple and direct. Complex multi-step prompts fail on smaller models (32B); break work into atomic units with clear stop conditions.
- *Fail-Safe Commits*: If any operation fails (edit, test, commit), stop immediately. Do not attempt workarounds that bypass the fail-safe; commit partial progress and report.
- *Cycle Document Safety*: Never modify =cycle/PROMPT.org= without explicit user approval. This is a process-defining file affecting all future sessions; propose changes first and wait for confirmation.

** Coding Style
- *Pure Functional Style*: Prefer pure functions. Use =let= for local bindings, avoid =setq= for global state. Functions should return values rather than mutate globals; use =defconst= for constants and =defvar= only when mutable state is necessary.
- *No Hardcoded Absolute Paths*: Use relative paths or environment variables. Never hardcode =/home/ncu/...= or similar absolute paths in code, scripts, or configs.
- *Implementation Layer*: Implement each capability in exactly one layer — Elisp, a shell script, or a tool-native config file — following =doc/IMPLEMENTATION-STRATEGY.org= (one owner per behavior). Tool-native settings are never mirrored in Elisp; ship a default native config (see =scaffold/templates/=) when defaults are needed.
- *No Elisp Wrappers Around Decoupled Designs*: Do not add Elisp that encapsulates data or wraps a design a tool already owns (init files, config files, native formats). Configure the tool through its own mechanism — e.g. ship a default =.gdbinit= rather than writing Elisp that overwrites it.

** Cycle Process
- *Cycle Goal*: Each cycle must have a clear, measurable goal
- *User Selects Items*: User must explicitly select backlog items for each cycle.
- *Capacity*: 2-4 hours per session
- *Review Findings*: After cycle review, add action items to =cycle/BACKLOG.org=

** Workflow & Governance
1. *Pick items* from =cycle/BACKLOG.org=
2. *Work in atomic commits* with cycle markers
3. *Post-Cycle*: Discuss findings, add action items to =cycle/BACKLOG.org=
4. *Record* delivered story points in =cycle/CYCLE-HISTORY.org=

The cycle process is machine-enforced via git hooks and =cycle/bin/local-ci.sh=.

*State Machine*:
Cycles follow a formal state transition: =PLANNING= → =ACTIVE= → =CLOSING= → =ARCHIVED=
- *ACTIVE*: Commits are permitted.
- *Other*: Commits are blocked unless a recovery path is used.

*Recovery Paths*:
If a commit is required while the cycle is not =ACTIVE=:
1. *One-time*: Use the =--recovery= flag with the commit validator.
2. *Persistent*: Set =git config cycle.bypass true=.

*Local CI*:
=cycle/bin/local-ci.sh= is the single owner of process validation, orchestrating:
- State-file schema validation.
- Governance checksum verification.
- Current-cycle state gating.

* Commit Convention

Extend conventional commits with cycle metadata:

#+begin_example
<type>(<scope>): <description> [C<N>] [Xsp] [#item]
#+end_example

- =[C<N>]= — Cycle number (required)
- =[Xsp]= — Story point estimate (optional)
- =[#item]= — Backlog item reference (optional)

The legacy =[S<N>]= marker is forbidden; use =[C<N>]=.

Example: =feat(lsp): add eglot for nix-mode [C13] [3sp] [#nix-lsp]=
